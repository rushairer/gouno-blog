# Go X.509 security baseline: 2026-10-21

## Observed release blockers

PR #377 starts from main `6105d5c7e81317b66d54b3471deb885c5fe8048d`. Its initial frontend-only diff did not change the Backend or Seed. Nevertheless, exact-head CI run `39571740363`, Seed job `119127344789`, failed the existing immutable govulncheck command on Go 1.27.2:

- `GO-2026-6809`: distrust compromised intermediate certificates in `crypto/x509`.
- Found in standard library `go1.27.2`; fixed in `go1.27.3`.
- govulncheck reported one symbol-level affected vulnerability and exited nonzero. This is not a reason to skip the Seed gate or suppress the advisory.

The same initial PR separately failed formatting of its new frontend test. That formatting was corrected independently. Neither failure is claimed as successful acceptance.

The next exact-head BFF compatibility run `39572348547`, job `119129383635`, confirmed the new Go image index could be pulled, then failed before BFF startup: Alpine now supplied `ca-certificates-20261020-r0`, which conflicted with the unavailable old exact pin `20260909-r0` in both runtime builds. Keep exact package pinning, but update it to the actual repository version rather than deleting the requirement. The Backend builder uses that same current pin as well.

## Minimal remediation

Both `blog-backend/go.mod` and `seed/go.mod` use Go 1.27.3. Both multiarchitecture Docker builders use the same 1.27.3-alpine index digest, and the existing toolchain checker raises its minimum from 1.27.2 to 1.27.3. CI continues to select Go through the existing module-specific `go-version-file` inputs.

Both backend/seed certificate package pins and the image-contract expectations use `20261020-r0`. The Seed unpinned-package regression now rejects an unversioned package followed by any whitespace/end-of-line, not merely one particular backslash spelling. Application dependencies, go.sum, runtime Alpine image pins, all other package pins, scanners, severity thresholds and BFF certificate verification remain unchanged.

The active executable security floor is now **Go 1.27.3**. The earlier October 8 minimum mentioned in historical notes is not permission to downgrade the active checker. Keep both module versions and both builder tags/digests aligned.

## Acceptance and operational boundary

Require exact-final-head Backend and Seed tests/vet/module verification/govulncheck, Backend race/security coverage, the real PostgreSQL suite, all triggered BFF compatibility and frontend/parity/browser gates, plus rebuilt images and unmodified Trivy/Grype gates. Record actual results in PR #377 rather than manufacturing local results; this environment could not resolve github.com for a local clone.

Rebuild and deploy the corrected images to update production binaries. Changing a module directive or publishing a new image does not update a running container. No production deployment or certificate-chain probing is performed by this patch, and no TLS verification bypass is permitted.
