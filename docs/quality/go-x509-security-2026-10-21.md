# Go X.509 and image security baseline: 2026-10-21

## Observed release blockers

PR #377 starts from main `6105d5c7e81317b66d54b3471deb885c5fe8048d`. Its initial frontend-only diff did not change the Backend or Seed. Nevertheless, CI run `39571740363`, Seed job `119127344789`, failed the existing govulncheck command on Go 1.27.2: `GO-2026-6809` in `crypto/x509`, fixed by Go 1.27.3. This was a symbol-level finding, not permission to skip the gate. An independent formatting failure in the new frontend test was also corrected without waiver.

BFF run `39572348547`, job `119129383635`, resolved the new Go builder but failed before BFF startup because the old exact CA package `20260909-r0` was unavailable; the actual Alpine resolver supplied `20261020-r0`.

Images run `39572868065`, frontend job `119131106317`, built the full frontend image, then Trivy reported a fixable HIGH `CVE-2026-108783` in libxml2, suggesting `2.15.4-r0`. Attempting to pin that version in the old full Nginx image did NOT produce an accepted build. Run `39573688358`, job `119133831564`, rejected incompatible/unavailable libxml2 and libexpat pins. The retained job and Alpine `3.24-stable/main/libxml2/APKBUILD` show the distro's `2.13.9-r2` branch and module requirements. A scanner's fixed version is not proof of an installable, ABI-compatible package in this base image.

## Final candidate design

### Patched Go and certificate baseline

Both module directives and both immutable multiarchitecture Go builders use Go 1.27.3. The existing checker enforces 1.27.3 and the unchanged x/net security floor; CI still selects Go through module-specific `go-version-file` inputs. Backend builder/runtime and Seed runtime use the observed `ca-certificates=20261020-r0` exact pin. Application dependency versions and go.sum stay unchanged.

### Minimal static-serving frontend runtime

The actual `blog-frontend/nginx.conf` contains static file serving, the existing SPA fallback, port 8081 and the security-header include. It does not use XSLT, njs or image-filter modules. Replace the full image with Docker Official Images `nginx:stable-alpine-slim` at immutable multiarchitecture index `sha256:3028fc1419f99b95c1c69f844bbaf49dc1b881750c51b497fc721ac4f02a14e6` (metadata: Nginx 1.30.6, Alpine 3.24.2).

Do not install the full image's unused XML/graphics dependency tree merely to keep obsolete package-marker tests satisfied. Retain exact patched `pcre2=10.49-r0` and `zlib=1.3.2-r1`, the same static assets, configuration, headers, non-root user and port. Package-absence checks replace obsolete optional-library pin assertions; no vulnerability is ignored. No cross-release repository, forced dependency installation or TLS bypass is introduced.

Required verification is behavioral, not only a source check: both architecture builds run `nginx -t` as the final non-root user. The loaded frontend image is started without host port publication and checked for non-root identity, valid Nginx configuration, absence of optional XML/graphics modules and libraries, identical index bytes for root and the Admin deep link, and all seven existing security response headers. Cleanup removes the disposable container. Trivy and Grype still scan the resulting image with unchanged blocking policies.

Image matrix `fail-fast: false` retains all three independent outcomes; any failed build/test/scan still fails the workflow. Existing concurrency cancels obsolete runs. This is not permission to merge a partial-green matrix.

## Acceptance and operational boundary

Require exact-final-head Backend/Seed tests/vet/module verification/govulncheck, Backend race/security coverage, real required PostgreSQL tests, BFF compatibility, frontend/parity/browser gates, all three rebuilt images, frontend runtime smoke and all six Trivy/Grype checks. Record actual results in PR #377; no local full suite is claimed because the execution container could not resolve github.com for a clone.

Production binaries need newly built and deployed images. A source change, passing PR or published image is not a running production deployment. No live deployment, external Provider call or authorized-operator recovery drill is performed here. Overall #338/#359 acceptance remains separate.
