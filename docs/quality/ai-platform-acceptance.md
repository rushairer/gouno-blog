## Exit conditions and work order

1. Close the confirmed locked Skill limit defect through the normal PR gates. Review immutable Skill authority across admission and execution (including version/trigger and configuration changes) using concrete tests, not speculative refactors.
2. Reconcile open AI issues with code, not historical TODOs; classify each as confirmed defect, explicit product hold, accepted residual with rationale, or missing evidence. Review selected failed-model replay separately: consumed retry ownership prevents repeated admission, not upstream fulfilment or a first explicit replay.
3. Verify representative integration cases on the exact candidate commit with the existing [database gate](database-tests.md), backend test/coverage/race/vet/vulnerability checks, frontend/seed/dependency/Compose and image/BFF gates. Preserve per-test evidence where available; no skipped required tests or coverage-floor reductions. No blanket guarantee from CI.
4. Move to platform-wide acceptance only after confirmed high-impact AI control defects are resolved and remaining risks are explicitly documented. Verify public and external API contracts, BFF, role boundaries, deployment identity, and actual browser/Showcase evidence separately; do not modify certified UI from this matrix. External staging, real recovery drills and production identity are pending unless independently evidenced. Connector remains frozen, not certified complete.
5. CMS admission is a later assessment, not authorization to create a new product line. No release, production deploy, secret changes, live Provider requests or production database inspection is authorized by this document.

Do not reopen verified narrow fixes without new evidence. If a required manual or local verification is unavailable, record the exact blocker and hand off rather than marking the stage complete.
