# 媒体生成尝试审计与核对

本轮接续 PR #345，跟踪 Issue #338。范围是完善证据，不开放自动恢复。实际验收结果以本轮 PR 对应提交的工作流记录为准，不把测试代码存在等同于测试已通过。

## 解决什么问题

同一个候选图片可以有多次人工发起的生成尝试。过去的审计只记录候选 ID，按时间取到的“最新审计”可能来自旧任务或旧版本程序，不能据此判断当前任务是否成功。

现在使用 `(media_candidate_id, generation_attempt)` 精确关联。生成服务接收领取任务时返回的尝试号，而不是结束时重新读取候选的当前值。数据库对非空关联建立唯一索引；历史数据不猜测、不回填。

## 写入顺序与失败处理

1. 领取候选的生成尝试，保留原有状态与尝试号保护。
2. 在调用 Provider 之前，写入并确认 `started` 审计。数据库错误、唯一键冲突、提交确认丢失或没有返回审计 ID，都停止这次外部调用。
3. 外部生成结束后，只按审计 ID、候选 ID、尝试号和 `status='started'` 更新该记录。成功写为 `succeeded`；不能确认结果的错误写为 `outcome_uncertain`。前置检查失败也可能直接留下不确定记录，但不解除候选的隔离。
4. 审计写入最长五秒。终态写入失败不重发生成请求；已有的 `started` 记录保留为未确认的证据。候选的最终关联仍使用上一轮建立的尝试号保护。

`started` 只说明允许进入外部调用阶段，既不证明请求已经发送，也不证明 Provider 已经执行或计费。审计 INSERT 已提交但确认丢失时，本次程序没有调用 Provider，数据库仍可能保留 `started`；不能凭这个状态自动重试。

新审计的 `created_at` 是记录创建时间，不是完成时间。它不参与尝试身份判断。终态审计成功也不等于候选链接已提交，更不等于媒体文件此刻仍存在；人工处理前仍需核对候选、媒体元数据、存储对象及外部结果。

## 管理员如何阅读核对接口

接口仍为：

```http
GET /api/admin/ai-media-generation-reconciliation?limit=50
```

保留原有管理员保护与 `1..100` 的条数限制，查询不修改任何数据。

| 字段 | 含义 |
| --- | --- |
| `generation_attempt` | 候选当前的生成尝试号。 |
| `latest_audit_*` | 按创建时间取到的最新记录，兼容原接口；可能属于旧尝试。 |
| `latest_audit_generation_attempt` | 最新记录自身保存的尝试号；历史记录可能没有。 |
| `latest_audit_matches_current_attempt` | 最新记录是否明确匹配当前尝试，缺少尝试号时为 `false`。 |
| `current_attempt_audit` | 独立按候选 ID 与当前尝试号匹配的记录；不存在时省略，不借用其他记录。 |

例如候选已经进入尝试 2，尝试 1 的前置失败记录却更晚写入：最新记录会显示尝试 1、匹配标志为 `false`，当前尝试证据仍显示尝试 2。旧版本程序迟到写入的无尝试号记录也不会遮蔽精确关联。

没有审计、审计失败、超过截止时间，都不能证明外部请求没有执行。接口不据此取消、重试、重新领取、挂接媒体或发布内容；人工恢复仍遵循已有的批准与证据核对流程。

## 升级与历史兼容

先执行迁移 `094_generation_attempt_audit.sql`，再运行依赖新列的程序。迁移保留旧记录和原有可空外键；删除候选不会级联清除审计。旧程序仍可写入原有终态记录，其尝试号保持 NULL。

混合版本期间，旧工作进程并不会自动获得“调用前强制审计”的保护。应完成升级并排空旧工作进程，再按新链路评估新任务。不能将本轮保证追溯到历史任务，也不要删除新列来配合旧程序回滚。

## 回归覆盖

单元测试覆盖身份校验、调用前落库顺序、数据库失败与确认丢失时零外部调用、取消后有界终态审计、敏感错误不进入审计，以及编辑器直接生成的兼容性。

真实 PostgreSQL 测试覆盖并发启动时只放行一次外部调用、重复/错配/终态更新拒绝、旧任务迟到更新、最新记录与当前尝试分离、读取不解除隔离，以及候选删除后审计保留。迁移测试使用真实迁移文件，从 093 升至当前版本并重跑，验证历史记录、旧写入方式和迁移账本。

## 尚未解决的边界

本地唯一关联不是 Provider 的幂等键，不保证第三方 exactly-once 执行或绝不重复计费。本轮不假定各厂商支持通用幂等请求头，也没有新增自动重试或人工恢复写接口。Provider 请求标识、账号/配置证据、官方幂等语义与留存期限、带权限和证据的人工决策仍属于 Issue #338 的后续工作。

另外，候选最终关联之后的补偿保护，与 `GenerationService` 内部首次创建媒体元数据的失败处理不是同一个边界。后者的提交确认丢失与存储对象保留需要继续专项核验；本轮不能据此宣布整个跨数据库/对象存储流程具备原子性。
