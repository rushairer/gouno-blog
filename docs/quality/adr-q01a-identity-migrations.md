# ADR Q01a：新安装迁移与历史身份回填

日期：2026-09-05。决策：用户批准实施；本地实现，未发布。基线 HEAD：`cdc84aaa3f8f506adce9ee96ef7187f79dddbf58`。

## 背景与历史修订例外

原 086 在空库要求 active Owner；088 也要求 Owner，并把无法匹配的 subject 归给最早 Owner；089 强制系统种子的创建者非空。仅添加末尾迁移无法越过前面的失败。用户明确批准此次定点修订，历史迁移通常不改写的约定继续有效。

修订文件：`086_community_principal_identity.sql`、`088_backfill_ai_principal_identity.sql`、`089_drop_legacy_identity_columns.sql`。新增 `085z_identity_backfill_preparation.sql` 与 `090_creation_origin_constraints.sql`。085z 按现有文件名字典序排在 086 前；不能改名。Connector 的迁移文件、源码和测试保持原样。

迁移器仍按文件事务提交，SQL 与 ledger 写入一起回滚；已提交文件保留。测试用相同执行器读取真实旧 SQL 构造升级数据库。原 086/088/089 的字节副本保存在 `blog-backend/internal/migrations/testdata/legacy/`，只供回归；没有手工伪造成功 ledger。

## 来源与授权

五个模板/版本表增加 `creation_origin`，响应可选且只读。数据库默认 human：必须有真实 principal；system：必须 NULL；legacy：保留历史有效 principal。来源没有成员资格、角色或授权能力，不新增 Principal、身份别名或 Owner。

系统种子识别使用真实 001–085 迁移生成的 68 条 SHA256 内容指纹：Agent 2、Skill 15、Skill Version 20、Workflow 15、Workflow Version 16。规范化采用 PostgreSQL JSONB 行值，排除行 ID、时间、principal 和新来源列；保留名称、键、完整内容、版本及关联 ID、旧创建文本等其余字段。已有 principal 不重新分类，已经执行 088 的实例不追认系统来源。仅匹配名称、system_key、空创建者都不足以通过。

这些指纹是保守的：旧库版本关系 ID 偏移或内容经过修改，即使运营人员认为它是内置模板，也不会自动认定。需明确身份映射；无法证明归属就停止升级，不编辑内容以冒充种子。外部证据另行证明系统来源的修复应单独审阅。

Starter Pack 的受控插入使用 system + NULL；移除最早 Owner/普通用户兜底。保留预算、审批和停用逻辑。冲突更新不覆盖现有创建来源。人类 API 创建及更新均以认证上下文提供操作者，忽略请求的创建者与来源；编辑原对象不改其原归属，新版本使用真实人类操作者。

## 历史人类记录

不使用裸 subject、邮箱或默认 Owner 推断。既有非空 principal 保留；缺失必需身份的记录仅接受操作人批准的精确 issuer + subject 映射，目标身份必须已存在。

批准数据独立保存原表/行/字段、原 JSON 值、issuer、subject、解析后的 principal、批准人、理由、证据引用及时间。相同原值的重复批准必须完全一致；来源值改变后可新增针对新值的批准，旧批准仍保留。整批事务，任一不合法全部回滚。迁移再次核对原值、精确身份和当前记录是否仍需人类身份。

访客评论不要求人类；没有审核行为的记录不伪造审核人。工作流 schedule_key，以及 Agent 的 cron + schedule_key 是独立调度证据；仅出现系统文本或 event 前缀不足以豁免人类映射。已有审核文本、审核时间或已审核状态要求身份。失败报告只列身份字段与记录定位，不输出完整业务内容或凭据。

## 升级兼容性

| 当前数据库 | 行为 |
| --- | --- |
| 空库 | 所有真实迁移执行成功；系统资源不创建 principal 或成员；Owner 沿用现有精确身份配置流程 |
| 086 前 | 准备迁移提交后，缺映射则 086/088 安全失败；批准后继续 |
| 已完成 086、未完成 089 | 保留已执行结果，处理仍存在的旧字段；089 删除前再次检查与回填 |
| 已完成旧 089 | 不重跑历史；新准备迁移建来源/证据结构，090 校正约束；旧身份、内容、角色和审计不自动重写 |

已删除的原身份文本无法从当前 principal 反向恢复。准备迁移快照记录现存但已失去源字段的归属；report 输出疑似历史归属供核查。新 API 创建的记录不会被当作旧 cutover 结果。旧模板来源标记 legacy，090 不自动撤销旧 Owner 归属。外部备份或审计证据是后续纠错前提。

有历史数据的实例升级前须备份，并停止并发旧版本写入与并发迁移。失败后补齐证据继续迁移，或恢复备份；不提供自动反向身份重写。本地回归不能代替具体实例的备份恢复演练。
