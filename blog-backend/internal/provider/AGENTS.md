# Provider text negotiation

The repository-root AGENTS.md is authoritative. Preserve its image-generation no-replay and request-evidence rules.

- OpenAI text streaming negotiation is shared by Responses and Chat Completions. Auto may retry with `stream:true` once only after the typed HTTP 400/422 classifier explicitly requires streaming. Never broaden this to every error containing `stream`.
- Return and unwrap the error from the request that actually failed. Do not replace a failed streaming request with the initial non-streaming 400, or retain that obsolete error as the primary cause. `errors.Is`, `errors.As`, retry classification and request evidence must select the final attempt.
- Explicit `never` serializes `stream:false`, never enables streaming, and identifies a required-stream configuration conflict. Explicit `always` serializes `stream:true` from the first request. A repeated rejection of an already-streaming request must state that true was sent, without looping.
- Legacy auto text-protocol discovery is allowed only for an initial HTTP 404/405. Do not switch protocols after authentication, quota, upstream 5xx, transport/decode errors, or after the selected endpoint already required streaming. Known Chat-only gateways should explicitly select `chat_completions`.
- Text negotiation helpers must not be used to reintroduce image-generation fallback or replay. Do not add generic idempotency headers or forward OpenAI-only client request identifiers to compatible gateways.
- Retain `openai_negotiation_test.go` alongside existing successful stream/tool-call tests. Count actual HTTP requests and assert final error type, status, request evidence and explicit stream flags; a happy-path fallback test alone is insufficient.
- Agent-level automatic text retry is permitted only for a typed HTTP 429 rejection, with the existing bounded attempt count. Do not classify retry eligibility from raw error text. Timeouts, cancellation, transport/decode failures, and 5xx may follow accepted/billed work; stop rather than blindly replay. This does not change the typed OpenAI protocol/stream negotiation rules or grant any image retry permission. Count actual HTTP requests and test misleading error bodies, ambiguous failures, explicit 429 recovery and already-cancelled contexts.
- Anthropic thinking/forced-tool compatibility negotiation is permitted only for typed HTTP 400/422 responses explicitly rejecting the relevant control. The optional third request requires a second explicit compatibility rejection; never remove forced tool choice and resend after auth, quota, server, cancellation, transport or unrelated validation failures. Preserve the actual final typed cause. Error-code classification covers typed native Anthropic/Gemini HTTP responses as well as OpenAI, without trusting arbitrary body text.
- Governed Agent text requests may supply the TextDispatchAudit port. Call it before every explicit HTTP dispatch, regardless of negotiation, and confirm a bounded terminal observation before returning the response or typed rejection. Audit failures are fixed local errors, not upstream retry or negotiation signals. Do not reuse this observer for image dispatch, forward new correlation headers, record a prompt/body/URL, or equate HTTP headers with parsed output or billing. Non-Agent callers remain outside this scoped audit.
- Non-stream text responses must also carry an explicit protocol completion reason: OpenAI Responses `completed`, Chat Completions `stop` or `tool_calls`, Anthropic `end_turn`, `stop_sequence`, `refusal` or `tool_use`, and Gemini `STOP`. Reject missing/unknown/incomplete reasons and malformed/duplicate Tool calls, preserve observed usage, and never dispatch partial output. Gemini `responseId` is retained as bounded correlation evidence when no request-ID header exists.
- Text SSE framing must reject malformed and truncated events. Chat Completions requires an explicit stop/tool_calls finish reason and matching complete Tool calls; Responses requires response.completed, not EOF, [DONE], or HTTP 200 alone. Ignore ordinary Responses message/reasoning output items as Tools. Reject missing IDs/names, duplicate call IDs, invalid or absent argument objects and conflicting terminal evidence. On failure return observed tokens and bounded request evidence only; no partial text or executable Tool calls. Do not replay incomplete/invalid/failed streams, and do not change the separate image decoder.
- A merged commit or successful image publication does not prove that a production container runs it. Never claim a live upstream incident is resolved without a new run and independently verified deployment identity.
