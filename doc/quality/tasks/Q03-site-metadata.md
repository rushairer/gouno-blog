# Q03：站点配置、元信息与标题测试稳定性

状态：planned。执行顺序：Q02 后；技术上不依赖 Q02 方案，但当前基线须包含已完成改动。

## 目标与范围

站点配置具备明确的读取、缓存和更新所有权；标题/SEO 在异步加载、路由切换和品牌更新后保持正确。定位首次 PostDetail 测试失败，不能把重跑通过当作修复。

主要入口：`src/api/site.ts`、`config/site-defaults.ts`、`hooks/useSiteMetadata.ts`、`hooks/usePageTitle.ts`、`utils/seo.ts`、公开页面和相关测试。本任务不决定 SSR/预渲染、不重写身份 SDK、不引入全局状态库作为默认答案。

## 实施步骤

1. 列出站点配置的请求者、缓存、模块级副作用、事件和元信息写入者；在基线下重现/分析标题失败，检查 cleanup、异步完成顺序和测试隔离。
2. 把已确认的产品缺陷与测试环境缺陷分别记录。缺失 Effect 依赖是代码观察，不自动等于标题失败根因。
3. 选取最小统一状态方案：请求去重、缓存生命周期、错误回退、明确订阅和卸载清理。只有实质收益时才引入新依赖，并说明理由。
4. 为 document title、description、canonical、OG 和结构化数据定义所有权与清理规则；异步站点响应不能覆盖当前文章元信息，旧路由 cleanup 不能覆盖新路由。
5. 保留站点设置更新和跨标签页更新行为，避免模块 import 发起不可控请求或永久监听。
6. 用可控 Promise/事件调度验证时序，补回归。不得删断言、只增加 sleep、忽略失败或配置自动重试来让门禁变绿。

## 验收

- [ ] 无缓存、缓存命中、请求失败、慢响应和更新事件均有验证。
- [ ] 多消费者同时需要配置时不会重复发起同一轮请求；重试与失效有明确规则。
- [ ] 文章标题与自定义品牌正确，异步品牌变化会更新相关元信息。
- [ ] A→B 快速切换、卸载、StrictMode 和请求晚到时不会恢复错误标题。
- [ ] 跨标签页及站点设置修改的预期行为保留；不遗留监听/卸载后副作用。
- [ ] 单测及全量前端质量命令通过；有针对性时序测试，而非仅依赖重复运行次数。
- [ ] 本地标准 HTTPS 观察标题、元信息和路由切换，无相关控制台错误；未能执行的浏览器范围明确列出。
- [ ] 说明首次失败根因；若仍未定位，应明确留下未解决项，不宣称已修复不稳定性。
